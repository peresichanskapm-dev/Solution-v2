# Next.js Starter Kit

## Общее

- Стартовый проект Next.js, подготовленный разработчиком для разработчиков.
- Автор — Vladyslav Dubinin (https://vladyslav-dubin.in).
- Бесплатно для некоммерческого использования; коммерческое — по согласованию с автором.

## Установленные пакеты

- AOS — библиотека анимаций, настроена и готова к использованию: https://michalsnik.github.io/aos/
- Lenis — плавный скролл и управление якорями: https://www.npmjs.com/package/lenis#events
- Swiper — единственный вариант для всех каруселей: https://www.npmjs.com/package/swiper
- ESLint и Prettier — кодстиль; перед коммитом: `npx prettier . --write`
- Sass — пишем стили только на нем

## Базовые правила

- Имена медиафайлов и переменных — camelCase.
- Верстаем в пикселях, но все px (>1) прогоняем через функцию `px-to-vw` для адаптации по ширине макета (функция в миксинах).
- Не оставляем комментарии у каждой строки; если код требует пояснений — переписываем. Допускаем комментарии только для логических групп (пример — `styles/globals.scss`).
- Медиафайлы храним в `public/media/НазваниеБлока/` (для каждого блока своя папка).

## Первичная настройка

1. Настроить цвета, брейкпоинты и нужные переменные в `src/styles/_variables.scss`.
2. Проверить и при необходимости дополнить миксины в `src/styles/_mixins.scss`.
3. Подключить шрифты в `src/app/layout.js`: https://ru.nextjs.im/docs/app/getting-started/fonts
4. Задать шрифты и общие стили в `src/styles/globals.scss`.
5. Добавить дефолтные метаданные в `src/lib/metadata.js` (структуру не менять).

## Структура проекта

- `src/app` — не трогаем `layout` (кроме шрифтов, хедера и футера). В `page` подключаем нужные блоки внутри `main`. Для мультистраничности следуем Next.js: https://ru.nextjs.im/docs/app/getting-started/project-structure
- `src/ui/blocks` — полноценные блоки; верстка блока начинается с `section` (кроме header/footer).
- `src/ui/components` — небольшие переиспользуемые компоненты (кнопки, ссылки, карточки и т.д.).
- Используем модульные SCSS, импорт через индексный файл, вспомогательные функции/хелперы держим отдельно (не 10 функций в одном компоненте).
- Пример структуры блока — `src/ui/blocks/Demo`.

## Lib

- `src/lib/context` — не-UI контексты (попапы, Lenis, анимации и т.п.).
- `src/lib/helpers` — хелперы для компонентов.
- `src/lib/metadata` — настройки метаданных; используем `buildMetadata` для дополнительных страниц.
- `src/lib/api` — все API-фетчи (по умолчанию серверные и кэшируемые).

## Правила стилей

- Desktop first с внутренними медиазапросами; обязательно используем миксины/функции/переменные (включая калькулятор vw и контейнеры).
- Для всех размеров в px применяем `px-to-vw(px, width)` (высоты тоже считаем от ширины макета). Допустимы %, vw, vh.
- Не используем BEM, Tailwind, Bootstrap, Mobile First.
- Классы называем понятно; `classes` максимум с 4 уровнями вложенности.
- Обычно шрифтов хватает в `globals.scss`; если их много — используем миксины.

## Медиа

- Все медиа (кроме svg) выводим через `<Image>` с `fill`; ширину задает контейнер с `position: relative` и нужным layout (flex/grid), изображение — с `object-fit`. Для svg используем <img> ванильный.
- Храним медиа в адекватном разрешении (обычно 2x к макету), без излишнего веса; формат — `webp`.
- Для каждого медиа — отдельный контейнер; без фиксированных размеров у `<Image>`.

## Метаданные и API

- Стандартные метаданные задаем один раз и расширяем через `buildMetadata` для других страниц.
- Все API-ключи храним в `.env` и `.env.example` (оба заполняем одинаково; в git уходит только example): https://nextjs.org/docs/pages/guides/environment-variables
- По умолчанию компоненты серверные; фетчи выполняем на сервере и кэшируем при необходимости.

## Полезные команды

- `npm i` — установка пакетов.
- `npm run dev` — запуск dev-сервера.
- `npx prettier . --write` — форматирование перед коммитом.
- `npm audit fix` — обновление уязвимых пакетов.
